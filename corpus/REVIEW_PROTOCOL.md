# 자가발전 시험지 검수 프로토콜 (SOP)

> 구독 요금제만으로(외부 API 0원) 시험지를 crop→OCR→렌더→검수해 **품질 코퍼스**를 쌓는
> 표준 작업 절차. 이번 중앙고 검수(2026-06-10)에서 겪은 함정을 박제해, 다음 시험지는
> 막힘없이 진행한다. **각 단계는 게이트** — 앞 단계 PASS 없이 다음으로 가지 않는다.

## 핵심 원칙 (이번에 비싸게 배운 것)

1. **"렌더 안 깨짐 ≠ 정상."** 반드시 **원본 크롭과 문항별 1:1 비전 대조**. 중앙고에서 렌더만
   훑고 "정상"이라 했다가 결함 11건을 놓쳤다. 전수 대조가 유일한 안전장치.
   - ⚠️ **역도 성립: "이상해 보임 ≠ 결함."** ground-truth(완료본/폼사양) 없이 우리 렌더만 보고
     "떠 보인다/이상하다"고 플래그하면 **false positive**가 된다. 중앙고 B6("27 답란 부유")이
     실은 폼 미주(endNote)의 표준 2열 넘침(27문항=폼 최대치 근처)이라 사람이 채워도 동일 —
     결함이 아니었는데 검수목록에 잔여로 오래 남았다. **"이건 폼/HWP 고유 동작인가?"를 먼저
     물어라**(미주·열·컨테이너 등 구조 확인). 완료본이 같은 모양이면 그게 정답이다.
2. **JSON 규약 위반(A)과 코드 버그(B)를 분리하라.** A를 먼저 깨끗이 제거하고 재렌더하면
   순수 코드버그만 남아 헛수고가 없다. (중앙고: A1 배점텍스트 제거 → 재렌더 → 순수 B만 디버깅.)
3. **결함은 가려져 있다.** 한 결함을 고치면 가려졌던 새 결함이 드러난다(배점이 메타란 토큰을
   가렸었다). **고칠 때마다 전수 재렌더·재대조**.
4. **COM/HWP는 비결정적.** 메타란 토큰 run 구조·캐럿 위치가 매 렌더 달라진다. 토큰 잔존 같은
   비결정 결함은 **3회 이상 렌더**해 항상 깨끗한지 확인(1회 성공은 우연일 수 있다).

> ⚠️ **크롭 bbox 추정 함정(경일중 2026-06-11)**: 다운스케일 그리드 오버레이로 y경계를
> 어림하면 **하단·우측 단의 2·3번째 문항에서 일관되게 ~0.05~0.13 위로 치우친다**(첫 문항
> =단 머리는 정확). 결과: 선택지 ③④⑤·박스·그림이 잘리거나 윗문항 꼬리가 섞임. → 2단계
> 게이트는 **재크롭 후 각 크롭을 실제로 열어 "번호~⑤ 안 잘림"을 전수 확인**하고, 잘리면
> y0/y1 을 내려 재크롭(verify-adjust 루프). 완료기반은 300dpi 페이지를 L/R×상하 사분면으로
> 쪼개 읽으면 판독이 선명하다(`PAGE_DPI` 높여 재추출).

> ⚠️ **하네스 필수단계(5a)**: corpus 캐시 렌더는 GUI 워커를 안 거치므로 figure 블록이
> `content_parser` 에서 통째 드롭된다(워커가 image 로 해소하기 전 단계). 렌더 전 `_figs_to_notes`
> 로 figure→안내문구 치환을 **반드시** 거쳐야 완료본 대조가 정확하다(상인고 #12 에서 확인).

### 후보 선별 자동화 + 완료본 레퍼런스 (2026-06-10 확립)

기출 폴더 구조: **`원본/`**(학생이 푼 사본 — 손풀이 많음) · **`pdf/`**(3단계 사람검수
**완료본 = 정답지**, 우리 폼 양식) · **`워드/`**(hwp 편집본). 깨끗한 인쇄본 원본이 거의 없을
때(고1 공수1 등 다 손풀이 사본), 두 가지를 쓴다:

1. **`corpus_select_clean.py`**(연필민감, 권장 — 2026-06-11): dpi100 + **연필 회색대역
   (저채도 중간톤)×1.5 + 색펜×4** 가중으로 *진짜 깨끗한 인쇄본*을 위로. **학교별 최선(가장
   깨끗한) 사본만** 대표, 완료본 보유·`--exclude` 기검수/골든 학교 제외.
   ```
   python scripts/corpus_select_clean.py "<원본폴더>" "<pdf완료본폴더>" <필터> \
       --exclude 조암중,중앙중,… --top 20
   ```
   구버전 `corpus_select.py`(dpi50·dark<110만)는 **연한 연필을 못 잡아** 깨끗도 1위가 연필
   범벅인 사고를 냈다(고산중 반려·revert). ⚠️ 자동점수는 1차 필터 — 상위 후보는 **`corpus_prep.py
   montage` + 개별 페이지 비전**으로 답란 백지 여부를 확인해 연필 잔존본을 탈락시킨다(같은 학교도
   사본별 깨끗도 상이, "(답안)" 표기본은 정답 기입본일 수 있어 제외, 180° 회전스캔도 탈락).
2. **완료본 = 정답지(ground truth)**: 완료본이 있으면 검수가 비약적으로 정확해진다. 원본
   변환 결과를 **완료본과 1:1 대조**하면 OCR 오독·렌더 결함이 즉시 드러난다(중앙고는 정답지
   없이 원본만 봐서 일부 놓침). 완료본이 pdf 로 없고 **hwp 로만 있으면** `워드/` 에서 찾는다.
   **원본이 손풀이로 너무 더러우면**, 완료본에서 문제 내용을 판독해 OCR JSON 을 만들고(입력
   노이즈 0) 우리 파이프라인으로 렌더해 완료본과 대조한다 — 순수 파서·렌더 결함만 잡힌다
   (완료본을 베끼는 게 아니라, 내용만 읽고 **변환은 우리 코드**가 한다).
3. **완료본 텍스트레이어 교차검증**(결정론·이미지 0, 2026-06-11 운암중에서 확립): 완료본 PDF가
   디지털(비상·동아 등 출판본)이면 **텍스트 레이어가 살아 있다**(`fitz` `page.get_text()`).
   수식은 이미지라 공백으로 빠지지만 **한글 발문·선택지 텍스트·`[서답형 N]` 라벨·정답표는 전부
   추출**된다. 이걸로 ① 내 OCR 발문을 #1~끝까지 전수 텍스트 대조(오독·누락 즉시 발견),
   ② **정답표와 내가 결정론적으로 계산한 답을 대조** — 일치하면 *수식 판독이 검증*된다(객관식은
   선택지를 직접 풀어 답번호를 맞춰 본다). **비전 이미지 예산과 무관**해 누적 이미지 상한에 걸려도
   가능하고, 텍스트 대조라 시각보다 정확하다. ⚠️ 단, 완료본 **어휘**가 원본과 다를 수 있으니
   (다른 사람 재타이핑) **확신 판독은 원본 우선**, 내 판독이 불확실했던 조사/어휘만 완료본으로
   보정한다(운암중 #5 조사 보정 / #3 '근'은 완료본 '해'와 달라도 원본 판독 유지).

## 세션 분리 운영 — OCR 세션 ↔ 렌더 세션 (2026-06-11)

HWP COM 은 동시 실행이 안 되므로(고아 Hwp.exe = 비결정 hang), 두 세션으로 파이프라인 분리:

- **OCR 세션(생산자)**: 0~4단계만. HWP 불필요. 산출 = `corpus/<시험지>/` (crops.json·
  `ocr/p{n}_merged.json`·`meta.json`). 4단계(lint `--json` FAIL 0) 통과 시 `meta.json` 에
  **`"status": "ocr_done"`** 을 찍어 핸드오프. 대기열 대시보드(예: `QUEUE_중1.md`)도 갱신.
- **렌더 세션(소비자)**: 5~9단계. `status: ocr_done` 인 시험지를 집어 렌더→대조→수정,
  완료 시 **`"status": "reviewed"`**.
- **소유권**: 핸드오프 이후 그 시험지의 OCR JSON 수정(8단계 A형 결함)은 **렌더 세션이 직접**
  한다 — 두 세션이 같은 JSON 을 만지는 경합 방지. OCR 세션은 넘긴 시험지를 다시 안 건드린다.
- ⚠️ **타이핑 혼입**: 렌더 세션이 COM 을 돌리는 동안 다른 세션(OCR)에 프롬프트를 타이핑하면
  변환 문서에 키 입력이 샐 수 있다(실측, `CONVERSION_VISIBLE=False` 여도). lint 자모 grep 이
  1차로 잡지만, 렌더 중에는 타이핑을 멈추는 게 안전.

## self-OCR JSON 작성 규약

`p{n}_merged.json` = `{"header":"", "questions":[ … ]}`. 각 question:

- **number**: 문항번호(정수). **score**: 배점(숫자, 소수 가능). 본문에 `[N점]`을 남겨도
  파서가 제거하지만, **`부분점수 있음` 등 부가문구는 생략**하고 score 필드로만 표기.
- **contents**: 블록 배열. 블록 type:
  - `text` — 평문. 한글·조사.
  - `equation` — 인라인 수식(LaTeX). 모든 숫자·문자·식. `\frac` `\mathrm{P}` `\leq` 등.
    - ⚠️ **발문 인라인 소수식은 한 text 에 묻지 말고 명시 `equation` 블록으로 분리**한다.
      `일차방정식 1-0.7x=-0.2x+1.7의 해` 처럼 소수가 든 식을 text 안에 두면 인라인 분리기가
      마침표에서 `1-0`/`.`/`7x =- 0`… 로 쪼갠다 → text 앞부분·뒤부분과 식을 별도 블록으로
      나눠 식을 latex_to_hwpeq 직행시킨다(마침표 분해 회피). 소수가 선택지 equation 인 경우는
      무영향. 범물중 #7(2026-06-11).
    - ⚠️ **강조마커 `__..__` 와 인라인 수식이 한 text 블록에 함께 있으면 그 블록의 인라인 수식이
      미추출되어 literal 로 남는다** → 인라인 수식을 **명시 `equation` 블록으로 분리**(강조마커와
      다른 블록). 격리 진단 확정: 강조마커가 같은 블록의 인라인 분리를 억제(선행부호 無관 — frac만
      있고 강조 없으면 정상 추출). 경구중 #12 `정비례 관계 y=-\frac{3}{2}x의 … 옳지 __않은__` 의
      `\frac` 가 literal 로 샘 → `text`+`equation`+`text` 3블록 분리(파서 확인). 위 소수식과
      동족(발문 인라인 수식 미분리 → 명시 블록 분리). (B형 근본원인이나 작성 분리로 회피.) 2026-06-11.
  - `equation_block` — **발문 아래 독립 디스플레이 수식**. 가운데 한 줄. **정의역까지 통째**
    포함(`P(X=r)=…(r=0,1,⋯,72)`). 인라인 EQUATION 과 구별해서 줄 것.
  - `table` — `{"type":"table","value":"","rows":[[…],[…]]}`. 셀은 LaTeX 가능.
  - `figure` — `{"type":"figure","value":"<설명>","bbox":[x0,y0,x1,y1]}`. **bbox 채울 것**
    (없으면 그림 미렌더). 현재 그림 자동삽입은 미구현이라 안내문구로 대체됨(알려진 한계).
- **choices**: 객관식 `[{"number":1,"contents":[…]}, …]`. 보기 박스는 `<보기> ㄱ. … • ㄴ. …`
  형태 text 로(라벨이 원본에 인쇄됐을 때만 `<보기>`/`<조건>`, 없으면 `<상자>`).
  - ⚠️ **원본 라벨이 `<보기>`/`<조건>` 이 **아닌** 경우**(예 `<단서>`·`<규칙>`): 파서·렌더가
    인식하는 라벨은 보기/조건뿐이라 **라벨없는 `<상자>` 로** 넣고, 발문 안의 그 라벨 텍스트
    (`주어진 <단서>를…`)는 **그대로 둔다**(파서가 `<단서>`는 박스 머리로 안 잡음). 경일중 #19.
  - **화살표 선택지**(이항 `2x-5=3 ➡ 2x=3+5` 등): `equation` 으로 `\rightarrow` 사용(→ 렌더).
    수식 **부분항 밑줄**(이항 항 강조)은 객체 내부 밑줄 미지원이라 표현 못 함 — LHS→RHS 쌍이
    정보를 보존하므로 생략(`__…__` 밑줄은 한글 강조 전용). 경일중 #3.
- **표 제목(병합 머리행)**: 표 윗칸에 병합된 제목(`전시관 입장료` 등)은 표 본문 rows 에 넣지
  말고 **표 바로 앞 짧은 TEXT 블록**(캡션)으로 분리한다 — 렌더가 캡션으로 인식해 줄바꿈 후
  우측정렬(합의 #8). 본문 rows 는 데이터만 직사각형으로. 경일중 #15.
- **박스 안 수식이 가로로 나란히**(연립 2개·등식 2개 등)면 한 text 에 **2칸 공백** 구분으로
  적는다(`<상자> \begin{cases}…\end{cases}  \begin{cases}…\end{cases}`) — 파서가 깊이 0
  더블스페이스를 수식 경계로 분리해 원본처럼 나란히 렌더한다(월암중 #5·#6, 2026-06-11).
  - ⚠️ **박스 머리 바로 뒤가 `\frac` 등 LaTeX 면 마커를 한 text 에 묻지 말 것**: `<상자> \frac…`
    을 한 text 로 주면 인라인 분리기가 마커의 `>` 를 수식으로 흡수해 `<상자 `+`> \frac…` 로
    깨진다(렌더 박스머리 매칭 실패) → **마커만 독립 text 블록 `"<상자>"` + 식들은 별도
    `equation` 블록**으로 준다(렌더가 박스 머리 이후 블록을 전부 박스 안에 소비). 쉼표 구분이면
    식 블록 안에 `, ` 두면 파서가 `eq1`+`, `+`eq2` 로 분리해 박스 안 나란히 렌더. 범물중 #20
    (2026-06-11). cf) `\begin{cases}` 는 env-atom 통째 매칭이라 한 text 라도 마커 보존(위 줄).
- **발문 선두의 `<보기> 중/에서 …` 참조는 원본 그대로** 적어도 된다 — 파서가 참조어를
  인라인으로 처리(박스 머리는 항목이 따라오는 블록만). 2026-06-11 전엔 박스로 오인했음.
- **sub_questions**: 소문항(서답형 `(1)(2)`). question 과 동일 구조.
- **label_type**: 서답형이면 `"서답형"`/`"서술형"`/`"단답형"` 명시(정답페이지 라벨 동기화).
  발문 선두 `[서답형 N]` 라벨도 contents 에 그대로 둔다(파서·렌더가 처리).

## lint 사용

```powershell
python scripts/corpus_lint.py --json "corpus/<시험지>/ocr"   # 4단계
python scripts/corpus_lint.py --xml  out.hwpx               # 6단계
python scripts/corpus_lint.py --all  "corpus/<시험지>" out.hwpx
```
FAIL=출력 깨짐(차단), WARN=알려진 한계/권장(통과). lint 는 **비전 대조(7단계)의 1차 게이트**일
뿐, lint PASS 가 곧 정상은 아니다 — 위치·레이아웃 결함은 PNG 대조로만 잡힌다.
