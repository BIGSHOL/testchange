사용자 지시로 수행한 조사 기록. 결론 요약과 재검토 시점의 재실행 방법을 남긴다.
관련 코드 박제: `core/ocr_engine.gemini_flash_no_think_config`(커밋 `71827e1`),
재실행 하네스: `scripts/gemini_flash_ab.py`.

## 1. Gemini 3.5 vs 3.6 Flash — 실측으로 미전환 확정

### 공식 가격 (2026-08-10, ai.google.dev)

| 모델 | 입력 $/1M | 출력 $/1M |
|---|---|---|
| gemini-3.6-flash | 1.50 | **7.50** |
| gemini-3.5-flash | 1.50 | 9.00 |

출력만 17% 싸다. 제3자 집계(pricepertoken 등)의 "3.5 가 $0.75/$4.50 로 인하" 표기는
공식 페이지와 불일치 — 공식 기준으로 판단했다.

### 실측 A/B (강동중 크롭 2장 × EXAM_OCR 프롬프트, 프로덕션 동일 조건)

| 구성 | 입력 tok | 출력 tok | 사고 tok | 호출당 비용 |
|---|---|---|---|---|
| 3.5 `thinking_budget:0` | 6,762 / 6,753 | 423 / 468 | 0 | $0.01395 / $0.01434 |
| 3.6 `thinking_level:"minimal"` | 동일 | **500 / 609** | 0 | $0.01389 / $0.01470 |
| 3.6 무설정(기본) | 동일 | 424 | **636 과금** | $0.01809 |

- **입력 지배 워크로드**: 이미지+8.9k자 프롬프트 ≈ 6.8k tok 이 비용의 ~70% → 출력
  단가 인하의 효과 상한이 애초 ~5%.
- **3.6 은 같은 내용을 pretty-print JSON 으로 출력** → 출력 토큰 +18~30%(순수 공백)
  이 인하분을 상쇄. 호출당 비용 −0.4% ~ +2.5% = 사실상 동률.
- 내용은 두 모델 동일(문항·수식·선택지 일치). 3.6 이 JSON 완결성 1건 우세
  (3.5 는 닫는 `}` 절단 1건 — `_extract_json` 복구 범위라 실해 없음).

### 3.6+ 로 전환할 때 필수 체크리스트 (이번에 절반은 미리 처리)

1. ✅ **`thinking_budget` 는 3.6+ 에서 HTTP 400** — `thinking_level:"minimal"` 만 받는다
   (minimal = 사고 0 실측). 엔진은 `gemini_flash_no_think_config` 가 모델 세대를 정규식
   분기하므로 config 로 3.6+ 를 넣어도 안 죽는다(crop_detector 공유).
2. ❌ 웹 `hwp-convert-web/api/_lib.ts` 의 `OCR_THINKING={thinkingBudget:0}` 은 REST
   `thinkingConfig` 라 **thinkingLevel 로 함께 바꿔야** 한다(한쪽만 바꾸면 결과물 갈림).
3. ❌ **figure-desc 는 figbench 98% 가 3.5 기준 튜닝** — 모델을 올리면 figbench(61문항)
   회귀가 필수. pro 서술은 요약 회귀로 이미 기각된 전례(9/13)가 있다.

## 2. Qwen3-VL / GLM

- **Qwen3-VL ≈ $0.21/M 입력**(제3자 집계) — Gemini flash($1.50)의 1/7로 유일하게
  유의미한 대안. 단 ① 한국 수학 시험지 + 우리 프롬프트 규약(corpus 60여 편 검수로
  축적) 충실도 미검증, ② 크롭 bbox 그라운딩은 Gemini 강점(crop_detector 실측 기록),
  ③ 전환 시 figbench + reviewed corpus 재검증 비용이 현 절감액(OCR 편당 수백 원)을
  압도. **물량 증가로 OCR 비용이 유의미해지는 시점에 재검토.**
- 검증 절차(2단계, 그때 쓸 것): ① `scripts/gemini_flash_ab.py` 의 MODELS 에 Qwen
  붙여 2크롭 스크리닝(API 호환·단가·프롬프트 추종 — 몇십 원). 통과 시 ② **reviewed
  corpus 3~5개교(60~100문항) 캐시 크롭에 돌려 reviewed JSON 과 diff 채점**(1~2천 원).
  결함은 꼬리에서 나온다("렌더 안 깨짐 ≠ 정상") — 2크롭 프로브만으로 전환 판단 금지.
  선행조건: 알리바바 Model Studio(국제판) API 키 + 결제 등록.
- **GLM**: 비전 변형(GLM-4.6V 계열) 가격이 공표조차 불명확(텍스트 GLM-5.2 $1.40/$4.40)
  → 후보 제외.

## 3. Mathpix

- Convert API ~$0.002/페이지, 한국어 지원, 수식·표·손글씨 LaTeX 전사 특화. 장점은 실재.
- 그러나 우리 파이프라인엔 부적합: **평면 문서 전사**(MMD/LaTeX)만 주므로 문항 구조
  JSON(`<보기>`/`<조건>` 박스·선택지 분리·배점·소문항)을 만들려면 **LLM 구조화 패스가
  또 필요**하고, LaTeX 방언이 달라 corpus 튜닝된 `latex_to_hwpeq` 후보정과 어긋나며,
  그림 서술(DeepSeek 입력)은 여전히 비전 LLM 몫. 현 OCR 비용(편당 수백 원)에선 절감
  여지 자체가 작다. **손글씨 복구·OCR 교차검증 오라클 용도의 백로그로만 유지.**
