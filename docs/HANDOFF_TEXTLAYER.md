# 텍스트 레이어 판독 — 인계 문서 (2026-08-13)

문제 DB 구축의 **비전 토큰 소모를 없애는 경로**. born-digital PDF 는 글자가 이미
파일 안에 있으므로 비전 없이 문항을 뽑는다. 이 문서만 읽으면 다른 PC·다른 세션에서
바로 이어받을 수 있다.

## 왜 만들었나 (실측 근거)

비전 판독 비용을 재 보니 **편당 24만 토큰**(풀이는 37만)이었다. 남은 1,837편이면
4억 4천만 토큰 — 주간 한도로 몇 달치다. 그런데 준비된 편의 70%가 born-digital 이라
**글자가 이미 PDF 안에 있는데 페이지를 이미지로 만들어 비전으로 읽고 있었다**.

| 작업 | 편당 토큰 | 툴콜/편 |
|---|---|---|
| 비전 OCR | 240,000 | 41~55 |
| 풀이(A/B 교차) | 370,000 | 10 |
| **텍스트 레이어** | **0** | 0 |

## 구성

| 파일 | 역할 |
|---|---|
| `db/pua_table.json` | HWP 수식폰트 사용자영역 코드 → 문자 (110종, 커버리지 100%) |
| `db/textlayer.py` | PDF → 문항 JSON. 분수·첨자를 좌표로 조립 |
| `db/textlayer_batch.py` | 일괄 실행 + 품질 게이트 |
| `db/scope.py` | 처리 범위(2024~2026 × 중1~3 + 고1) 단일 정의 |

```
python db/prep_pages.py --pdf-only --limit 900   원본 PDF 확보(PNG 렌더 없음)
python db/textlayer_batch.py --limit 1200        판독 → db/ocr_pilot/<id>.json
python db/textlayer.py --exam 5171 --show        한 편 확인
python db/textlayer.py --verify                  비전 판독물과 일치율 대조
python db/ingest.py                              DB 적재(2차 게이트)
```

## PUA 표를 어떻게 얻었나 (재현 방법)

수식은 `U+E0xx` 사용자영역 코드로 들어 있다. 폰트가 **서브셋이라 cmap 이 없고**,
글리프 이름은 라틴 템플릿 잔재라 못 믿는다(`E035` 가 'A' 로 나오지만 실제로는 '2').

그래서 **이미 비전으로 읽은 141편의 선택지 8,662개를 1:1 정렬해 실측 유도**했다.
길이가 정확히 같은 선택지만 써서(정밀도 우선) 빈도 투표 → 29종이 지지도 100%.
나머지는 문맥으로 확정(`E052`=',' `E05C`='√' `E04B/E04C`='{}' `E09D/E09E`='α/β'
`E101`='|' `E04F`=':' `E0B4`='ω' `E03E`='!'). **추측으로 채운 칸은 없다.**

구조 블록: 대문자 `E000+k`, 소문자 `E0E5+k`, 숫자 `E034`~`E03C`=1~9, `E03D`='0'.

## ⚠️ 비싸게 배운 함정 (다시 밟지 말 것)

1. **`get_text("dict")` 는 span 까지만 준다** — 분수·첨자는 글자 단위 좌표가 있어야
   조립되므로 `"rawdict"` 를 써야 한다.
2. **분수막대 글리프의 bbox 는 전각 상자**다. `y0` 로 위아래를 가르면 분자와 분모가
   **전부 뒤집힌다**. 실제 선은 상자 한가운데(`(y0+y1)/2`)에 있다.
3. **읽기 순서는 PyMuPDF 문서 순서(blk, ln)를 그대로 쓴다.** y 좌표로 재정렬하면
   인라인 분수의 분자 줄이 위에 있다는 이유로 **문항 머리를 앞질러** 경계가 깨진다
   (#2 발문이 #1 마지막 선택지로 빨려 들어갔다).
4. **정답면 판정을 낱말로 하면 안 된다.** `'풀이 과정을 쓰시오'` 는 서술형 발문에
   흔해서 거기서 자르면 뒤 문항이 통째로 사라진다(25문항 → 16문항 적재, 감사가
   잡았다). 반대로 `'정답'` 만 찾으면 해설면을 놓친다. → **번호가 되돌아가는
   지점**을 쓴다(정답 목록은 1부터 다시 시작). 형식과 무관한 신호다.
5. **수식 폰트에서 온 중괄호는 이스케이프**해야 한다. 연립방정식 `{` 나 집합
   `{x|…}` 가 그대로 나가면 LaTeX 구조용 중괄호와 섞여 균형이 깨진다(154건).
   `decode()` 한 곳에서 처리한다 — 본문의 평범한 괄호는 건드리지 않는다.
6. **박스 항목은 라벨 순으로 재배열**한다. 2~3열 배치일 때 지면 읽기 순서(행 우선)와
   라벨 순서가 어긋난다(작성자가 세로로 (가)(나)(다)를 채운다). 발문이 라벨로
   항목을 가리키므로 라벨 순서가 의미상 옳다. 자를 때는 **줄 문자열에 정규식**을
   건다 — 글자 단위로 끊으면 여는 괄호가 떨어져 `( • 가)` 로 망가진다.
7. **박스 검출은 O(n²)** 라 벡터 격자·그래프가 있는 면(선 수백 개)에서 멈춘다.
   `_LIMIT=120` 으로 건너뛴다(그런 면은 애초에 그림 면이다).
8. **모듈은 import 시 stdout 을 가로채면 안 된다.** `textlayer.py` 가 그랬더니
   부르는 배치 실행기가 print 에서 죽었다 → `if __name__ == "__main__"` 안으로.
9. `ingest.py` 가 `ocr_status='done'` 으로 바꾸므로, JSON 을 지우고 재추출하려면
   **`pending` 으로 되돌려야** 배치가 다시 집는다(안 그러면 조용히 건너뛴다).
10. `MATH_UNI`(∅∩∪⊂ 등)는 PUA 가 아니라 **유니코드 그대로** 실린다. 수식으로 안
    치면 런이 거기서 끊겨 `A={` / `∅` / `,{` 로 조각난다.

## 품질 게이트 — 통과분만 저장한다

`textlayer_batch.gate()`. 하나라도 어긋나면 **저장하지 않고 비전으로 넘긴다**.

- 문항 15개 이상, 번호가 1~N **연속**
- 객관식 선택지가 정확히 5개
- 미확정 글리프(`⟨XXXX⟩`) 없음
- **인쇄된 배점과 추출한 배점의 개수·합이 일치**

⚠️ 기준이 *"배점 합이 100인가"* 가 아니라 **"인쇄된 것을 다 담았는가"** 인 이유:
학원 대비 편집본은 실제로 114.6점이거나 배점이 일부만 인쇄돼 86.6점이다(둘 다
추출은 정확했다). **시험지 사정을 결함으로 오인하면 멀쩡한 판독을 버린다.**

## 실측 정확도

비전으로 읽은 141편과 대조:

| 항목 | 결과 |
|---|---|
| 문항 수 일치 | **141/141편** |
| 배점 일치 | **100%** |
| 본문 일치(그림 없는 문항) | 중앙값 **96.3%** |
| 그림 검출 | 30/40 일치, 오탐 4 |

남은 차이는 대부분 **표기 관례**다 — 비전은 `\mathrm{A}`·`~`·`\varnothing`,
텍스트 레이어는 `A`·`,`·`∅`. `content_parser` 가 어차피 로만화하므로 실질 동등하다.

## ⚠️ 통과율에 대한 정직한 수치

처음 샘플에서 잰 **83% 는 편중된 값**이었다(이미 비전으로 읽었던 편들 = 형식이
얌전한 것들). 학교·양식이 다양한 전체 물량에서는 **born-digital 중 통과가 그보다
훨씬 낮다.** 주요 탈락 사유:

| 사유 | 성격 |
|---|---|
| 수식 글리프 없음 | 진짜 스캔본 — 비전 필수(개선 여지 없음) |
| 배점 누락 | 소문항 배점 일부 미검출 — **개선 여지 큼** |
| 선택지 5개 아님 | 선택지 배치가 특이하거나 정답면 혼입 |
| 분해 실패 | 문항 번호 패턴이 다름 |

## 다음에 할 일 (효과 큰 순)

1. **소문항 배점 검출 보강** — 가장 흔한 탈락 사유. `(1)`·`①`·`1)` 등 마커 변형과
   `[총 N점]` 부모 배점 처리.
2. **선택지 배치 변형 대응** — 2열·표 형태 선택지.
3. **그림 문항 보강** — bbox 는 이미 기록돼 있으므로, 그 자리만 잘라 비전에 넣으면
   페이지 전체를 읽는 것보다 훨씬 싸다(아직 미구현).
4. **스캔본은 비전 유지** — 배치 크기를 10~12편으로. 30편은 한도에 걸릴 때
   **산출물 없이 275만 토큰**을 태운다(실측).
