### 1-1. 왜 만들었나 (전부 실제 결함에서 나왔다)

- **왕선중 q11 의 접선이 접점 D 를 10.03px 비껴간 채 `lint_svg` CLEAN 으로
  출하됐다**(사용자 지적). 원인은 접선 방향벡터를 손으로 `(sin, -cos)` 라고 적어
  부호를 틀린 것 — 반지름과 70°(접선이면 90°)를 이뤘다. 2D 린트는 겹침·잘림만
  보므로 "닿는가"를 아무도 검사하지 않았다.
- 정사영 그림은 좌표를 눈대중으로 찍어도 lint 를 통과한다. `verify_figure` 는
  2D 길이·각만 잰다.
- 한 그림 안에서 점 이름 15 · 각도 10.5 · 치수 12.5 로 글자 크기가 제각각이었고,
  그림마다 viewBox 가 달라 같은 15 라도 크게/작게 보였다.
- 좁은 각에 라벨을 넣으면 halo 가 변을 지우고(lint 규칙 7), 안 지우려고 멀리
  밀면 어느 각인지 모호해진다.
- **이 세션에서 내가 낸 결함**: 그림엔 `y = 3` 이 인쇄됐는데 실제 평면은 `y = 4`
  였다. 방정식 라벨을 검산하는 수단이 없었다.

### 1-2. 새 API 요약

**`core/figure_solid.py`** (신규, 표준 라이브러리만)

```
Plane / Plane.through / Plane.xy / plane_from_equation(a,b,c,d)
foot · project_points · dihedral_angle · line_plane_angle · area · projected_area
View(사방투영, 교과서 겨냥도) · Camera(정투영, 곡선이 주인공인 그림)
circle3 · split_by_depth · plane_intersection · equation_text
verify_solid(feet=·angles=·areas=·lengths=·equations=·perpendicular=·on_plane=·view=)
```

- `Camera` 는 정규직교 시선기저라 **구가 정확한 원, 3D 원이 정확한 타원**이 된다.
  사방투영으로 구를 그리면 구 위의 원이 구 밖으로 삐져나온다.
- `verify_solid` 는 `figure_svg._VERIFIED` **같은 등록부**에 기록한다. 따라서
  빌드 하네스의 `unverified(S)` 가 2D·3D 를 한 그물로 본다. 따로 관리하면 3D 쪽
  누락이 조용히 빠져나간다.
- `View`·`Camera` 둘 다 `collapses()` 가 있다 — 시선과 나란해져 평면이 선으로
  뭉개지는 시점을 `verify_solid(view=...)` 가 걸러 준다.

**`core/figure_svg.py`** 추가분

```
tangent_dir / tangent_seg / tangent_beyond      접선을 접점 기준으로
verify_figure(tangents=, on_line=, on_circle=)  닿는가/지나는가 (픽셀 절대오차)
leader(end_dir=…)                               직선/곡선 지시선 + 화살촉
angle_label_leader / angle_label                각 라벨 정책 진입점
point_labels                                    점 이름 자동 배치
type_scale(vb_w, vb_h, role)                    그림 크기 비례 + 크기 통일
curve_path                                      샘플 점열(속성 길이 한도 자동 준수)
shaded_sphere                                   허용된 유일한 참조 형태
```

- **`angle_label` 이 표준 진입점이다.** 넓고 자리가 있으면 안쪽 halo, 좁거나
  막혔으면 지시선. 판정은 눈대중이 아니라 라벨 상자와 도형 선·원·기존 라벨의
  실제 충돌로 한다.
- 지시선은 각이 열린 방향과 많이 어긋나면(기본 40°) **곡선**으로 감아 들어온다.
  직선으로 뒤에서 들어오면 화살표가 각과 반대를 향해 어색하다(사용자 지적).
- ⚠️ `angle_label(arc_r=)` 은 같이 그리는 `angle_mark(r=)` 과 **같아야** 한다.
  다르면 화살촉이 호에서 뜬 허공을 가리킨다(기본값은 둘 다 20).

**`core/figure_quality.py`** — 참조 SVG 전면 차단에서 **구 음영 한 경우만** 개방
(사용자 승인 2026-08-13, "특정 경우에만"). `<defs>` 안 그라데이션 + `fill/stroke`
의 `url(#id)` 만 허용. pattern·filter·mask·clip-path·외부 URL·`href` 상속·끊긴
참조는 종전대로 차단이고 테스트로 박제했다. **직접 `<defs>` 를 쓰지 말고
`shaded_sphere()` 를 통해서만** 넣는다 — 허용 형태가 한 곳에 모여야 나중에 안 샌다.

## 2. 미해결 — 레퍼런스 배치 재현

사용자가 제시한 두 참고 그림(구+두 평면 정사영 / 두 평면 위 원뿔곡선)의 **배치를
비슷하게 맞추는 데 실패**했다. 시점을 여러 번 바꿨지만 한쪽이 좋아지면 다른 쪽이
망가졌고, 이유는 짐작이 아니라 측정으로 확인했다.

### 2-1. 레퍼런스가 기하적으로 자기모순이다

참고 그림에서 정사영 점선 `P→P₁`·`Q→Q₁` 은 **화면상 수평**이다. 그러려면 고도가
0 이어야 하는데, 고도 0 이면 적도가 **직선으로 뭉갠다**. 그림은 적도를 타원으로
그려 놨다 — 두 조건은 동시에 성립하지 않는다.

| elev | +y 의 화면 수직성분(0이어야 수평) | 적도 단축/장축(0이면 직선) |
|---|---|---|
| **0** | **0.0** ✓ | **0.000** ✗ |
| 17 | −21.7 | 0.292 |
| 30 | −37.2 | 0.500 |
| 45 | −52.5 | 0.707 |

### 2-2. 두 평면을 동시에 반듯하게 보이는 시점이 없다

두 평면(`y=4`, `y+√3z+8=0`)의 법선이 **둘 다 yz평면에 있어서** 한 항이 커지면
다른 항이 상쇄된다.

| 시선 방위 | `y=4` 면 정면도 | 기울어진 면 정면도 | 결과 |
|---|---|---|---|
| 음수 (−45~−70°) | 0.73~0.92 | **0.17~0.28** | 아래 평면이 납작 |
| 양수 (+50~+60°) | 0.73~0.80 | 0.63~0.74 | 둘 다 보이나 `y=4` 가 기울어 보임 |

즉 참고 그림은 **손으로 그린 도식**이고, 사각형 꼭짓점도 계산이 아니라 눈으로
찍은 위치다. 정투영으로 유도하는 한 같아지지 않는다.

### 2-3. 이어받을 사람이 고를 두 갈래

1. **실제 문항 조건으로 작도** (권장) — 구의 방정식, 점 P·Q 좌표, 두 평면 식을
   받아 그대로 유도한다. 배치가 짐작이 아니게 되고 `verify_solid` 검산이 전부
   걸린다. 화면 배치는 참고 그림과 달라도 **수학적으로는 그 그림보다 정확**하다.
2. **도식(schematic) 모드 신설** — 사각형 꼭짓점을 화면 좌표로 직접 지정하고,
   정사영 점선을 수평으로 긋고, 적도를 지정한 타원으로 그리는 별도 경로.
   겉모습은 참고 그림과 거의 같아지지만 "이 그림이 진짜 투영이다"라는 보장을
   포기한다(3D 사실 검산은 별도로 유지 가능).

⚠️ **어느 쪽이든 시점을 손으로 더 만지는 방식은 권하지 않는다** — 이 세션에서
10회 넘게 반복했고 수렴하지 않았다.

- 통계 그림의 **도수 계산**은 `np.histogram` 에 맡기는 게 안전하다. 손으로 짠
  계급 클램프는 범위 밖 값을 양 끝 계급에 조용히 몰아넣어 도수가 틀린다
  (실측: 이상치 2개에 합 50→52). 렌더는 SVG 엔진 유지.
  matplotlib 전면 도입은 기각됐다 — 근거는 메모리 `figure-engine-keep-svg`.
- 구 음영 외의 그라데이션 용도가 생기면 `figure_quality` 의 허용 범위를 넓히기
  전에 **막혀야 할 것들의 테스트부터** 확인할 것
  (`tests/test_figure_generator_quality.py::LocalGradientAllowanceTests`).

## 4. 작업 원칙 (이 세션에서 비싸게 배운 것)

1. **라벨을 손으로 놓지 말 것.** `point_labels`·`angle_label` 이 충돌을 보고
   고른다. 손으로 dx·dy 를 적으면 그림을 조금만 고쳐도 다시 선을 밟는다 —
   이 세션에서만 같은 수정을 열 번 넘게 반복했다.
2. **라벨 값은 계수·좌표에서 생성할 것.** `equation_text(*EQ)` 처럼. 손으로 적은
   순간 작도와 갈라지고, 갈라진 걸 사람이 못 본다.
3. **"게이트 통과 = 정상" 이 아니다.** 접선이 접점을 비껴가도, 평면 방정식이
   틀려도 lint 는 CLEAN 이었다. 새 종류의 그림을 그리면 **그 그림이 주장하는
   명제를 검산에 추가**하고 넘어갈 것.
