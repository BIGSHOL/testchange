# 02 — 기출 도형 작도법 (세션 변환에서 그림을 그리는 법)

시험지 한글화의 세션 변환은 원본 그림을 **잘라 붙이지 않고**, 문제 조건으로 좌표를 계산해 **다시
그린다**. 사진만 예외(원본 크롭 + 노이즈 정리). 2026-08 ~ 10 실전 14편(중1~고2, 그림 170여 장 —
`corpus/*/fig_svgs.py` 집계)에서 사용자 검수로 굳어진 방법이다. 엔진 API 자체(FigureSpec v2 문법 등)는 todays-math
`docs/planning/09-figure-engine-guide.md` 가 이미 자세하니, 여기는 **그 엔진으로 기출을 옮기는 순서와
판단**을 적는다.

```
원본 확대·판독 → 좌표 계산(조건에서) → 기계 검산 → 작도(스펙 우선, 모자라면 프리미티브)
   → 픽셀 검수 → 원본|작도 나란히 육안 대조 → PNG(흰 바탕) → 지면 폭 = viewBox × 0.17mm
```

코드는 `core.figure_exam`(패치 01) 하나로 따라 할 수 있다 — `examples/ex_solid_foot.py`(입체),
`examples/ex_plane_spec.py`(평면).

---

## 1. 판독 — 무엇을 그릴지 정한다 ★

- **인쇄된 것만** 그린다. 학생 필기(숫자·호·√17·동그라미·점)는 뺀다. 판별은 확대해서 **굵기·번짐을
  인쇄된 표시와 비교**하고, 한 시험지 안에서는 **한 기준**으로(오성중 2026-10-12: 공통각 자리의 번진
  점 = 필기로 판정, 사용자도 "점 표기 하지 말 것"으로 확정).
- 판단이 갈리는 것은 **뺀 사실을 기록·보고**해 사람이 고르게 한다(`meta.json` `uncertain`).
- 원본에서 **선분 개수를 센다** — 실선·점선·보조선. 오성중 6번 원뿔에서 단면 원 안의 **반지름 선분**을
  빼먹어 지적받았다. "원본|작도 대조에서 선 개수 세기"가 체크리스트 1번.
- 숫자를 그림에서 읽어야 하는 문항(산점도·모눈)은 고배율로 **전수로 센다**. 가려서 못 세면 학생 답으로
  메우지 말고 불확실로 남긴다.

## 2. 좌표 — 조건에서 계산한다(눈대중 금지) ★

- 평면: `sss`(세 변 → 꼭짓점) · `foot`(수선의 발) · `isect`(교점) · `polar`(각도) · `figure_svg` 의
  `circle_pt`·`seci`·`tangent_isect`·`tangent_seg`(접선은 **접점 기준**으로 긋는다).
- 그래프: `frame(ox, oy, s)` — **x·y 단위를 같게(등방)**. 대진고 공수2(2026-08-18)에서 가로 1.93배로
  늘린 그림이 포물선을 눌러 기울기·직각이 거짓말을 했다.
- 입체: **3D 좌표를 먼저** 세우고(실제 길이) 사투영한다 — `oblique(origin, s, depth_ratio, depth_deg,
  zs)` 또는 `figure_solid.View`. 교과서 공간도형은 원근이 아니라 **사방(cabinet) 투영**이다(mplot3d
  원근은 평면이 과하게 눕고 수선이 뭉개져 기각, 2026-08-13).
- 원본이 일부러 비례를 바꿨으면(높이 과장 등) 따라가되 **기록**한다. 제일고 서술형 4: AE=1 을 2배
  높이(zs=2)로 — 아랫면은 z=0 이라 수선의 발 I 의 위치(EI:IG=9:16)는 정확하다.
- 답이 그림 안에 있으면 **답을 assert** 한다(그림이 문제와 같은 세계인지): 제일고 10번 건물 높이
  `10√11` 로 3D 좌표를 세우고 ∠CAB=60° 를 assert.

## 3. 검산 — 라벨값과 그림이 맞는지 기계로 ★

렌더가 멀쩡해도 "15:17 이라고 적었는데 1:3 으로 그린" 그림이 나간다(오성중 q2·q8·s2, 2026-08-13).
비율 붕괴는 눈으로 안 잡힌다 — **기계 검산이 유일한 방어선**.

| 함수 | 보는 것 |
|---|---|
| `figure_svg.verify_figure(name, lengths=, arcs=, angles=, tangents=, on_line=, on_circle=)` | 길이·호 비율(척도는 중앙값), 각(도), 접선(중심-선 거리 = 반지름, px), 점이 선/원 **위** |
| `figure_solid.verify_solid(name, feet=, angles=, areas=, lengths=, equations=, perpendicular=, on_plane=)` | 3D 길이, 수직, 정사영의 발, 이면각, S′=S·cosθ, 그림에 적은 평면 방정식 |

- `unverified(S)` / `build_figures` — 숫자 라벨이 있는데 검산을 안 부른 그림이 있으면 **빌드가 멈춘다**.
  "게이트를 만들어도 부르지 않으면 없는 것과 같다."
- ⚠️ 검산은 **내가 쓴 좌표가 내가 쓴 라벨과 맞는지**만 본다. 문제 조건을 잘못 읽으면 둘 다 틀린 채
  통과한다 → 5절의 육안 대조가 빠질 수 없다.
- 길이와 호는 한 척도 풀 — 단위가 다르면 이름을 나눠 따로 부른다("q5", "q5-지름").
- 왕선중 q11(2026-08-13): 접선이 접점을 10px 비껴간 채 lint CLEAN 으로 나갔다 → `tangents` 검산이 생겼다.

## 4. 작도 ★

### 4-1. 어느 경로로

| 경우 | 경로 |
|---|---|
| 점·선분·원·각·치수로 된 평면 도형 | **FigureSpec v2**(`FigureSet.spec`) — 엔진이 점 이름·각 라벨을 충돌 없이 배치 |
| 스펙이 못 그리는 일부(점이 끼어 나뉜 구간의 치수, 화살표, 음영 띠) | 스펙 + `pre`/`post` 덧그림 — 좌표는 **반드시 `sh(p)`** 로 옮긴다(엔진이 여백 때문에 캔버스를 평행이동) |
| 입체·모눈·그래프·삽화 | 프리미티브 직접(`FigureSet.raw`) + `fit` 으로 viewBox |
| 사진 | 다시 그리지 않는다 — 원본 크롭 정리 |

- ⚠️ 스펙 `dimensions` 는 **한 선분**에만 걸린다. 점 H 가 낀 BC 처럼 여러 선분에 걸친 치수는 `post` 에서
  `adim` 으로(사대부중 2026-10-06).
- ⚠️ 덧그림은 엔진의 캔버스 계산에 안 들어가 **잘린다** → 이름 두 글자 보이지 않는 점(`"Zz"`)으로
  캔버스를 넓힌다(기본 라벨은 대문자 한 글자만이라 안 찍힌다). `ex_plane_spec.py` 가 실제 사례.

### 4-2. 표기 규칙(사용자 확정)

| 요소 | 규칙 | 도구 |
|---|---|---|
| 점·도형 이름 | **정자**, 선·면 **밖**에. 흰 halo 로 선을 끊어 앉히면 위반(도형을 못 읽는다) | `pt_label`/`rtext` |
| 변수·문자 | 이탤릭, 숫자·기호는 정자, `°` 는 위첨자 | `ltext`(label_markup) |
| 단위가 붙은 수치 | 전부 정자(`30 m`) — ⚠️ `ltext("m")` 은 한 글자 m 을 변수로 기울인다 | `rtext`·`adim(upright=True)` |
| 길이 치수 | 양끝이 꼭짓점에 닿는 **볼록한 점선**, 라벨은 곡선 **바깥**. 길이 라벨이 있는 구간은 빠짐없이 점선 | `adim`(o 부호 = 볼록한 쪽, 법선 `(-uy, ux)`) |
| 각 표시 | 호는 두 변의 **실제 방향각 사이**만. 각 라벨은 이등분선 위 halo | `figure_svg.angle_mark`·`halo_angle` |
| 직각 | 두 참조점에서 방향 계산(단위벡터 손 하드코딩 금지 — 왕선중 q5) | `rangle_at`·`rangle` |
| 같음 표시 | 변에 **수직**인 짧은 선분(사선 금지) | `eq_tick` |
| 근호 | 유니코드 √ 금지(가로줄 없음) — 선으로 | `sqrt_label` |
| 분수 | 분자·분모를 쌓고 변수 이탤릭·숫자 정자(대진고 q16 분모 a 가 정자였다) | `frac_label` |
| 숨은 모서리 | 가는 점선 `w=1.0, dash="5 4"` | `HIDDEN` |
| 면 음영 | 앞면 옅게 `#ececec`, 옆면 진하게 `#c6c6c6` | `poly`·`box_parts` |
| 굵기·크기 | 본선 1.9 · 치수/표시선 0.6~0.72 · 라벨 16.8(RPM 정본 비, todays-math 에서 확정) | 엔진 상수 |
| 축 | 원점을 지나 튀어나가지 않게. 축을 옮기면 **눈금 라벨도 함께** | — |
| `<보기>` 상자 안 그림 | 상자는 **문서의 진짜 표**, 그림은 그 안에 — 상자 틀·제목까지 그림으로 굳히지 않는다(오성중 2번 지적) | — |

## 5. 검수 ★

- **`lint_svg(svg) == []` 이 완성 판정**(사용자 2026-08-12 "이걸 왜 완성되었다고 하나"). 실제 렌더
  픽셀로 본다: 잘림(viewBox 밖 잉크) · 라벨-선 겹침 · 라벨-라벨 겹침 · 선에서 떠 있는 길이 라벨 · 점
  이름이 선을 가림 · **halo 가 실선을 지움**(halo 만 씌우면 실선을 얼마든 지워도 통과하던 구멍 —
  41장 lint OK 중 11그림 15라벨이 실선을 지우고 있었다).
- 의도한 예외만 `lint_exempt` 에 **이유 주석과 함께**(예: 원본처럼 음영 면 안에 둔 꼭짓점 이름 — lint
  는 음영도 잉크로 센다; 글자 40개 넘는 그림은 픽셀 검수 한도 초과 → 육안으로 대신).
- 그다음 **원본 크롭 | 작도**를 나란히 놓고 육안 대조 — 선 개수, 점선/실선, 라벨 위치, 비례.
  "렌더가 안 깨졌다 ≠ 맞다", "몽타주가 그럴듯하다 ≠ 맞다"(두 차례 반려 실측).
- 그림 크기를 바꾼 뒤엔 lint 를 **다시** 돌린다.

## 6. 출력

- PNG 는 resvg(`svg_to_png_bytes`, 폭 900px 기본). **투명 배경은 문서에서 검게 변한다** → 넣기 전
  `flatten_white`.
- 지면 폭 = **viewBox 폭 × 0.17mm, 상한 68mm**(`width_mm`). 모든 그림에 같은 배율을 쓰면 어느 그림이든
  라벨 ≈ 8pt, 본선 ≈ 0.32mm 로 **같은 크기**로 인쇄된다. 그림마다 폭을 손으로 정하면 글자 크기가
  제각각이 된다(2026-08-13 지적).
- 보기 표 안 그림은 칸 안쪽 폭 이하(시험지 한글화 중2 폼 93.8mm).

## 7. 지면 삽입 — 한글(HWP) 전용 ✕

시험지 한글화는 그림을 **자리표시로 넣어 레이아웃을 잰 뒤, 모든 후처리가 끝난 마지막에 진짜 그림으로
교체**한다(`core/figure_embed.replace_placeholder_figures`). 한글 COM 이 폼의 기존 이미지(머리말 배너)를
재사용하는 버그와, 보안경고 제거 재저장이 XML 로 넣은 그림을 버리는 동작 때문이다. todays-math 는 자체
HWPX writer 라 해당 없음 — 다만 "그림 크기를 mm 로 고정해 넣고, 레이아웃 계산과 최종 삽입이 같은 mm 를
쓴다"는 원칙은 같다.
