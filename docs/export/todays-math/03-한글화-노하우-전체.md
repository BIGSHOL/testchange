## 1. 쪽 이미지·크롭 ○

- 쪽 이미지는 300dpi. 세션에서는 75dpi 미리보기 좌표(621×878)로 bbox 를 읽고 원본 해상도로 자른다.
  출처: `corpus/[제일고]…/_work/crop.py`
- ⚠️ 다운스케일 격자로 y 경계를 어림하면 **단의 2·3번째 문항이 0.05~0.13 위로 치우친다** → 자른 뒤
  "번호~⑤ 안 잘림"을 전수 확인하는 루프. 출처: `REVIEW_PROTOCOL.md` 2단계
- 크롭 프롬프트 규칙: 인쇄된 것만(학생 풀이 구역 아래로 내려가지 않기), 인접 박스 세로 비중첩,
  정답표·채점기준 페이지는 `class="answer"` 로 제외. 출처: `core/crop_detector.py` `_CROP_PROMPT`
- 크롭 y 드리프트(문항 한 블록 아래로 밀림)는 프롬프트로 못 막는다 → **결과가 비정상일 때만**(본문 25자
  미만) 위로 0.10 넓혀 1회 재판독. 출처: CLAUDE.md "웹 그림이 안내문구로 떨어진 두 원인"
- 답지 페이지가 문항으로 섞이면 라벨 재부여까지 죽는다 → 모델 판정 + 결정적 안전망
  (`drop_answer_key_questions`: 뒤쪽 연속 구간만, 절반 이상이면 판정 폐기). 출처: "대륜고 공수2 웹 변환 검수"
- 페이지가 뒤섞인 PDF는 **인쇄 문항번호로 재정렬**(객관식·서답형 각각, 번호가 모두 다를 때만).
  출처: "배포 변환 5건 수정 — 경상여고"

## 2. 판독(OCR) — 원문을 다룰 때 ◆

- JSON 규약: `{"header", "questions":[{number, score, contents[], choices[], sub_questions[], label_type,
  answer, solution, topic, difficulty}]}`, 블록 `text`·`equation`·`equation_block`·`table`·`figure`.
  출처: `REVIEW_PROTOCOL.md` "self-OCR JSON 작성 규약"
- ⚠️ 비전 모델은 단일 크롭을 구조화 JSON 으로 읽으면 긴 지문·확률분포표를 **요약하며 통째 누락**한다
  (같은 모델이 "그대로 전사"에선 충실). → 전사 2-pass 로 빠진 문단 복구, 표 지시어가 있으면 표만 따로
  전사. 프롬프트 강화로는 못 막았다. 출처: "OCR/파서 후보정 교훈 — 확통"
- 이미지를 프롬프트 **앞**에 두면 충실도가 오른다(캐싱은 포기).
- `<보기>`/`<조건>` 은 박스 테두리에 **인쇄됐을 때만**, 없으면 `<상자>`. 발문의 "다음 조건을" 을 라벨로
  환각하는 일이 잦았다.
- 배점은 **인쇄 표기를 문자열로 보존**(`3.0점` vs `3점` — 값으로는 절대 구분 못 한다, 휴리스틱은 108편
  회귀로 폐기). 출처: "대륜고 공수2"
- 서답형/서술형 → **서술형으로 통일**, 단답형은 유지(다른 유형). 라벨은 여러 경로로 새므로 파서·writer·
  저장 후 안전망 세 곳에서. 출처: "서답형/서술형 라벨 = 서술형으로 통일"
- 소수식·강조 밑줄이 섞인 발문은 수식을 **명시 equation 블록**으로 떼어 준다(마침표·`__` 가 인라인 분리를
  깨뜨림). 가로로 나란한 수식은 **2칸 공백**으로 구분.
- ⚠️ 모델에게 **JSON 으로 LaTeX 를 받지 말 것** — `\frac`·`\theta`·`\times`·`\neq` 의 `\f \t \b \n` 이
  JSON 이스케이프로 먹힌다(`\neq` 의 `\n` 은 복구 불가). 구분자 포맷(`###ANSWER###` …)으로 받는다.
  출처: "정답·해설·메타 자동 생성을 배포 exe 로"

## 3. 조판 규칙 — 지면에 공통 ★

| 규칙 | 핵심 | 출처(CLAUDE.md) |
|---|---|---|
| 점·도형 이름 = 정자, 좌표 = 이탤릭 | `rm A it {(2,~3)}`. ⚠️ 한글 수식 `rm` 은 **다음 `it` 까지 전부** 번진다 — `rm P(a,b)` 는 a,b 까지 정자 | 도원중 중1 |
| 점이면 로만 — 1차원 좌표도 | 수직선 위 `A(-1)` 도 정자 | 메모리 point-roman-1d |
| 첨자·프라임 점 이름 | `A_1C_1`·`P_n(n, f(n))`·`A'B'` 도 기하 문맥이면 정자 | 고2 미적분 파일럿 · 각·도·프라임 |
| 확통 기호 | 확률변수 X·Y·P·E·V·N·Z **이탤릭**, 순열 `P_`·조합 `C` 정자. 비기하 단일 대문자(선수 A·B)는 이탤릭 | 학남고 확통 |
| 행렬 | 행렬곱 `AB` 는 이탤릭(기하 선분 AB 와 다름 — '행렬' 문맥) | 상원고·대진고 공수1 |
| 각 | `cos A`·`∠A` 의 A 는 정자, 변 a·b 는 이탤릭 | 상인고 |
| 단위 | 정자 + 얇은 공백: `5 rm`cm`, 변수+단위 `a rm`cm`, `1L`·`xkm`·`kcal`. 모평균 `m`·함수 `g(x)` 는 단위 아님 | 범물중·월서중·수2 3교 |
| 도·각 기호 | `90^\circ` → `90°`(위첨자로 또 올리지 않음), 각 = `ANGLE`, 합성 `\circ` = ∘ | 각(ANGLE)·도(°)·프라임 |
| 닮음/부정 | 이항 `\sim` = ∽, 단항 = ∼(프라임 뒤도 피연산자) | 대륜고 · 사대부중 |
| 부정 선택문 | "옳지 **않은** 것" 의 부정어 볼드+밑줄(뒤에 '것'이 올 때만) | 출력 합의 #11 |
| 선택지 2열 | 길이 판정은 **보이는 글리프 근사**(LaTeX 원문 길이 금지 — `\sqrt` 가 부풀어 1열 강등) | 중앙중 중3 |
| 집합 중괄호 | `\left\{…\middle|…\right\}` → `LEFT { … RIGHT | … RIGHT }`(자동 크기). 리터럴 `"{"` 는 고정 크기 | 해설 수식 크기 + 조건제시법 |
| 극한 첨자 | `lim`·`max`·`min` 첨자는 **아래**(`lim _{x->0}`) — 빈 그룹 `{}` 를 끼우면 오른쪽 첨자 | lim 첨자 회귀 |
| 수식 크기 | 해설 수식도 본문 글자와 같은 pt(수식 객체는 자기 baseUnit 으로 크기가 정해진다) | 해설 수식 크기 |
| 박스 | 보기/조건은 윗테두리에 라벨이 박힌 병합 표, 박스↔선택지 빈 줄 없음, 박스 첫 줄 빈 단락 없음 | 출력 합의 #3 · 다사중 |
| 배점 | 객관식 발문 끝 인라인. 서술형은 인라인 우선, 줄이 넘칠 때만 줄바꿈 우측정렬 | 출력 합의 #2 |

## 4. 수식 변환 LaTeX → 한글 수식 ★ (vendor 에 있음 — 패치 02)

함정 목록(전부 `core/latex_to_hwpeq.py` 에 반영):
- 키워드 치환은 **앞뒤 공백 보장** — `P\left` → `PLEFT`, `X\le` → `XLEQ` 로 붙어 리터럴.
- 매핑이 없는 명령은 **조용히 사라진다**: `\lt`/`\gt`(부등호 증발), `\varnothing`(∅ 증발), `\overarc`,
  `\%`. **분리기**(`content_parser._LATEX_CMD_RE`)에도 같이 등록해야 한다 — 매핑만 있고 분리기가 모르면
  `₩therefore` 처럼 새어 나온다(장산중).
- 접두 매칭 사고: `\mid` 가 `\middle` 을 먹음, `\lim` 가 `\limits` 를 먹음(`lim lim its`).
- 명령 직후 한글(`\pi일`) — `\b` 경계가 한글을 단어 문자로 봐 명령 미인식 → `(?![a-zA-Z])` 경계.
- 라벨이 수식 키워드와 겹침: `rm {GE}` 가 ≥ 로 렌더 → 따옴표로 감싼다(프라임이 붙어도 연속 대문자면 키워드).
- 수식 안 한글 사이 공백은 한글이 죽인다 → `~`(따옴표 리터럴 안은 제외).
- `\text{g}` 단위는 평문 단위로 풀어야 정자+간격이 붙는다. 유니코드 위첨자(`2²`) → `2^{2}`.

## 7. 정답·해설·메타 ◆

  읽혀 다르면 둘 다 싣고, 해설 프롬프트가 본문과 일관된 쪽을 고르게 한다. Pro 는 요약해 더 나빴다(9/13).
  원본 서술을 **지우지 말고 병기**(교체하면 원본에만 있던 표 숫자가 사라졌다).
- 비용 실측: DeepSeek V4 Pro 해설 20문항 ≈ ₩65(경원고 기하, 정답 20/20).

## 8. 품질 게이트·검수 원칙 ◆

1. **렌더가 안 깨짐 ≠ 정상** — 원본과 문항별 1:1 대조만이 안전장치(렌더만 훑고 결함 11건 놓침).
   역도 성립: "이상해 보임 ≠ 결함" — 양식 고유 동작인지 먼저 확인.
2. 입력 규약 위반(A)과 코드 결함(B)을 나눠 A 부터 걷어낸다.
3. 결함은 가려져 있다 — 하나 고치면 다른 게 드러난다. 고칠 때마다 전수 재렌더·재대조.
4. 비결정 결함은 3회 이상 돌려 확인.
5. **확대 전 결함 단정 금지** — 저해상도 오판이 여러 번 원본 확대로 기각됐다.
6. lint PASS ≠ 정상 — 위치·레이아웃 결함은 이미지 대조로만 잡힌다.
- 영향권 산출: 고칠 때 전 corpus 를 **고치기 전/후 파서로 돌려 결과가 달라진 문항만** 재렌더(전수 재렌더
  쳇바퀴 회피). 달라진 것이 전부 개선 방향인지 확인 = 회귀 0 판정.
- 자동 게이트 예: 출력 텍스트의 한글 음절이 입력(OCR + 양식 상용구)에 없으면 **타이핑 혼입**, 본문 평문에
  남은 ASCII 토큰도 혼입(본문 영문·숫자는 전부 수식 객체여야 하므로). 출처: 오성중 중2

## 10. 운영 함정 ○

- Bash 인라인 스크립트의 백슬래시는 도구 레이어에서 한 꺼풀 벗겨진다(`\t`→탭, `\f`→폼피드, 정규식
  `\m` bad escape) → 백슬래시 든 코드는 파일로 써서 실행.
- Git Bash `$PWD` 를 윈도우 파이썬에 넘기면 `/d/…` 가 `D:\d\…` → `cygpath -w`.
- 내려받은 파일은 비신뢰 — 새 빈 폴더에, 파이썬은 `-I` 로.
- 병렬 에이전트가 공용 임시폴더 같은 파일명을 쓰면 **다른 시험지를 읽는다** → 대상별 `_work/` 격리,
  검증은 형식이 아니라 내용 정합(배점 합·정답표)으로.
- 한글 프로세스를 이름으로 죽이면 사용자가 열어 둔 미저장 문서가 날아간다 → 자동화 인스턴스
  (`-Automation -Embedding`)만 정리.
- 변환 중 한글 창을 보이게 두면 사용자 키 입력이 변환 문서로 샌다(숨겨도 드물게) → 혼입 게이트.
- 여러 세션이 한 저장소를 쓰면 `git add -A` 금지(남의 미커밋 파일), 커밋 전 pull.
- Supabase 무료 프로젝트는 무활동 16일이면 정지 — 다운로드·로그·캐시가 죽는다.
