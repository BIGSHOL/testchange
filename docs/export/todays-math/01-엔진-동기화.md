## 1. 패치 01 — `vendor/figure-engine/core`

### 1-1. ⭐ `lint_svg` 가 todays-math 에서 안 돌던 것 (`figure_svg.py`)

```text
>>> sys.path.insert(0, r"D:\todays-math\vendor\figure-engine")
>>> from core.figure_svg import lint_svg; lint_svg(<선 하나 SVG>)
ModuleNotFoundError: No module named 'core.figure_generator'      ← 2026-10-21 실측
```

`lint_svg` → `_ink` 가 래스터화를 `core.figure_generator._svg_to_png_bytes` 에서 빌려 썼는데,
`figure_generator` 는 Claude 호출·`utils.config`(API 키)까지 끌고 오는 모듈이라 벤더에 없다.
todays-math 는 지금 `lint_svg`·`assess_svg(run_pixel_lint=True)` 를 부르는 곳이 없어 드러나지
않았을 뿐이다(`figure_quality.assess_svg` 는 이 실패를 `pixel lint failed: …` 로 바꿔 **반려**한다).

- 수정: `figure_svg.svg_to_png_bytes(svg, width)`(resvg_py, 주석 제거, 실패 시 None)를 엔진 안에
  두고 `_ink` 가 그것을 쓴다. 시험지 한글화의 `figure_generator._svg_to_png_bytes` 는 이제 이걸
  감싸 로그만 덧붙인다. 래스터 결과는 종전과 바이트 동일(10-19 에 만든 제일고 PNG 5장 중 4장 일치 —
  나머지 1장 q9 는 PNG 를 만든 13:42 뒤 13:59 커밋에서 그림 크기를 고친 것으로 보인다).
- 함께: `unverified(svgs, scope=None)` — 검산 등록부는 "어느 스크립트가 `verify_figure` 를
  불렀나"로 갈라 두는데(시험지끼리 `q1` 이 겹치지 않게), 공용 빌더가 스크립트 대신 확인하려면
  스크립트 경로를 넘겨야 한다. 인자를 안 주면 종전과 같다.

### 1-2. 새 모듈 `figure_exam.py` — 기출 재작도 공용 도구

세션 변환 시험지마다 `fig_svgs.py` 머리에 복사돼 있던 헬퍼를 모았다. 기존 스크립트(제일고 고2
기하·오성중 중2)와 **출력이 바이트 단위로 같다**(헬퍼 비교 36건, PNG 5장). 쓰는 법은
`02-기출-도형-작도법.md`, 실행 예는 `examples/`.

| 덧그림 조판 | `ltext`(변수 이탤릭) `rtext`(전부 정자) `pt_label` `curve_pt` `adim`(바깥 치수) `dots` `poly` |

### 1-3. 새 모듈 `figure_spec_repair.py` — 모델 FigureSpec 자동 정리

시험지 한글화 웹 실사용 스펙 77개(Supabase `api_cache`)를 실측하니 **54개(70%)가 컴파일 실패**였고,
대부분 도형이 아니라 모델이 붙인 **장식 칸**(라벨 `pos` 68곳, 치수 `dashed` 14, `style` 5 …)이나
**범위 밖 값**(치수 `side`, 진한 채색) 때문이었다. 정리 후 같은 77개에서 스펙 작도 23 → 35.

- 원칙: 엔진은 모르는 칸을 **일부러** 거부한다(오타를 삼키지 않으려고). 그 원칙은 두고 **그려지는
  결과가 같은 것만** 벗긴다. 뜻을 실을 수 있는 칸(`label`·`text`·`value` …)이 섞이면 하나도 안
  벗기고 실패. 엔진 오류 문구를 보고 그 자리 **하나만** 고쳐 다시 컴파일(스키마 사본을 두지 않는다).
- 각의 변 판정이 `선분 길이 × 1e-7` 이라 좌표 어림에 못 견딘다 → 빗나감 1.5 이내면 점을 선분 위로
  (두 변이 다른 선분이면 **교점**으로). ⚠️ 옮긴 좌표를 반올림하지 말 것(±5e-5 로 다시 빗나간다).
- 기각한 것 2: 치수 빼고 재시도(값이 사라진다), 빠진 변 선분 보태기(5건 중 2건이 없는 선을 만듦).
- `semantic_inventory_issue(scene, desc)`: 모델이 먼저 쓴 전사(desc)에 없는 라벨, 스펙에서 빠진
  점을 잡는다(35°/35 degrees, √11/`\sqrt{11}` 같은 표기 차이는 맞춰 본다).
- ⚠️ 오류 문구 정규식이 읽는 엔진 문구 6종은 todays-math `figure_scene` 에도 **그대로 있다**(확인).

| 고친 것 | 전 → 후 | 날짜·출처 |

## 3. 연결(선택) — 제품 경로에 스펙 정리 넣기

`scripts/figure/render_spec.py` 는 지금 `render_figure_spec(spec)`(= `compile_figure_spec(spec)
.render_svg()`)가 던지면 그대로 실패한다. 정리를 끼우려면:

```python
from core.figure_spec_repair import SpecRepairFailed, compile_with_repair
...
        else:
            try:
                _scene, svg, _repairs = compile_with_repair(spec)   # 호출자 spec 은 안 바뀐다(사본)
            except SpecRepairFailed as exc:
                fail(f"도형을 그리지 못했습니다: {str(exc)[:200]}")
                return
```

판단은 todays-math 몫이다 — 그쪽은 이미 모델에게 기하를 고치게 하는 수리(`figure-repair.ts`)가
있고, 치수 자리가 없으면 치수를 빼는 정책(발문이 값을 말하므로)이라 우리와 사정이 다르다.
장식 칸(`pos`·`dashed`·`style` …) 때문에 버려지는 스펙이 실제로 있는지 한 번 세어 보고 정하면 된다.
